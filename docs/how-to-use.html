Getting started

Create a production

A production folder keeps your brief, sources, revisions and review records together.

Availability: Available

  1. Choose New in the sidebar.
  2. Choose a folder name and location in Create production folder, then confirm.
  3. Check the production name and folder shown in Studio.

Notes & limits

  • The suggested location is Movies/Codex Studio in your home folder. Cancel leaves your current selection unchanged.
  • Wait for any current action, or stop the running Codex task, before changing projects.

Getting started

Continue an existing production

Open the production folder itself to recover its saved state.

Availability: Available

  1. Choose Open.
  2. Select your existing production folder and confirm.
  3. Check its name and folder before editing.

Notes & limits

  • Opening fails safely if the folder is not a valid production; do not create a replacement over valuable files.
  • The app remembers the last saved project selection. Unsaved screen drafts are not a recovery system.

Getting started

Move through the workspace

The sidebar follows the production process.

Availability: Available

  1. Start with Brief & sources, then Understanding.
  2. Use Review for playback and feedback, Resources for preferences, and Codex & QA to request work and inspect checks.
  3. Use How to Use whenever you need instructions.

Notes & limits

  • Most editing and generation features are requested in Codex & QA; Studio is not a full timeline editor with one button per skill.
  • Save drafts before switching tabs or projects. Help for this tab opens over the current screen so you can read without leaving it.

Getting started

Know what is saved

Explicit save buttons matter. Refresh reads current saved project records.

Availability: Available

  1. Use Save brief, Add link, Save annotation, Record evidence or the relevant status button to store the change you are making.
  2. Wait for completion and check any notice or error.
  3. Choose Refresh to reload saved project state after outside work.

Notes & limits

  • Refresh does not save unfinished text. Brief drafts are preserved during refresh unless you explicitly reload them; switching screens can discard other local drafts.
  • Resource choices save when selected. The Codex model choice is remembered separately. Prompt text, evidence selections and resolution notes are not project autosave.

Getting started

Hand the current project to Codex

Export handoff creates a current project summary and copies its text.

Availability: Available

  1. Save the brief and feedback you want included.
  2. Choose Export handoff.
  3. Paste the copied text into the intended Codex conversation if you are working outside Studio.

Notes & limits

  • Send to Codex prepares this handoff automatically. The handoff includes saved sources, brief, routes and version-bound feedback.
  • Export handoff exports instructions and context, not a finished video.

Getting started

Start a first edit

Begin with source understanding and a small preview.

Availability: Available

  1. Create a production, import footage and save a brief.
  2. In Codex & QA, ask Codex to explain the source and prepare an edit strategy before cutting.
  3. Read the findings, then request a representative preview.
  4. Review the actual video and add specific feedback before a full edit.

Notes & limits

  • Short synthetic examples prove parts of the tools work. They do not qualify every kind of raw footage or a finished creative result.
  • Codex is online; context and review material sent to it are not an offline-only workflow.

Example request

Read my saved brief and sources. Document source understanding and an edit strategy, flag uncertainty, and propose a short representative preview before substantive cutting.

Brief & sources

Resolve a changed saved brief

Studio prevents your draft from overwriting a brief changed elsewhere.

Availability: Available

  1. When the saved-brief warning appears, copy any draft text you want to keep.
  2. Choose Reload saved brief to replace the screen draft with the current saved brief.
  3. Reapply your intended changes and choose Save brief.

Notes & limits

  • Reload saved brief discards the current draft. Saving a changed brief reassesses dependent reviews; earlier evidence may become stale.

Brief & sources

Import footage or documents

Import copies into the production while preserving originals.

Availability: Available

  1. Choose Import footage or documents and select one or more local files, or drop files in the import area.
  2. Wait for the import notice.
  3. Check the listed labels and source or document roles.

Notes & limits

  • PDF, TXT, MD, DOCX, JSON and CSV are classified as documents; other imports use the source role. Importing a document does not prove Codex has read or understood it.
  • Review is for media playback; documents are not shown in its Viewing picker.

Brief & sources

Add a source, reference or background link

Give each link a role so Codex knows why it is here.

Availability: Available

  1. Enter a descriptive Label and the URL in https://….
  2. Set Use as: Source for material to work from, Reference for a comparison or example, or Background for context.
  3. Choose Add link. Click a saved link to open its destination.

Notes & limits

  • Adding a link records it; it does not automatically download or analyze its contents. Explain which parts matter in the brief or Codex request.
  • Linked material is source information, not permission to change your workflow or account.

Understanding

Record evidence that already exists

Record completed stage evidence stores an assessment, not a substitute for work.

Availability: Available

  1. Choose Stage under Record completed stage evidence.
  2. Explain what was established and where it is documented.
  3. Choose Select evidence files and select the actual evidence files.
  4. Check the selected paths, then choose Record evidence.

Notes & limits

  • A reason and at least one evidence file are required. Required artifacts and earlier stages must be current.
  • Ask Codex to perform routine checks and record its findings; do not fill in passing evidence for work no one reviewed.

Understanding

Read the authoritative workflow

The stage definitions come from a local editable workflow file.

Availability: Available

  1. Choose Open authoritative workflow.
  2. Read the stage instructions and allowed routes in the opened file.
  3. If a workflow change is needed, describe it to Codex and reassess affected reviews afterward.

Notes & limits

  • The file is config/studio-workflow.json in the engine repository. Editing it changes the workflow; opening it only displays it.

Review

Play a source or revision

Viewing selects the exact version you want to review.

Availability: Available

  1. Choose a source or revision in Viewing.
  2. Use the inline player controls to play, pause and seek.
  3. Choose another item in Viewing to compare versions.

Notes & limits

  • Feedback stays attached to its original version. The unresolved count covers the entire production, not just the selected item.
  • Switching selected media clears frame/region/transcript selections. Save the current annotation first. Playback pauses when you leave Review.

Review

Add a rendered revision

A revision is an output version, separate from original footage.

Availability: Available

  1. Choose Add revision.
  2. Select the rendered media file you want reviewed.
  3. Choose the new version in Viewing.

Notes & limits

  • Codex can also register actual output revisions. Importing a revision alone does not certify its quality or resolve earlier feedback.

Review

Leave a frame or time-range note

Pause & annotate captures a real frame from the selected version.

Availability: Available

  1. Seek to the issue and choose Pause & annotate.
  2. Wait for Frame captured for this version and check the displayed time.
  3. Enter What should change here, and why?.
  4. For a range, enter Optional range end (seconds) after the captured start time; leave it blank for a single moment.
  5. Choose Save annotation.

Notes & limits

  • A captured frame and comment are required. Times are seconds in the form 12.5; invalid or out-of-range values need correction.
  • The captured presentation time can differ slightly from the requested time. The saved note records this exact version and frame.

Review

Mark an area of the picture

Draw region adds a rectangle to your captured frame.

Availability: Available

  1. Choose Pause & annotate first.
  2. Turn on Draw region and drag over the relevant part of the picture.
  3. Use Clear region to remove the box or draw again to replace it.
  4. Add your comment and choose Save annotation.

Notes & limits

  • The rectangle follows the picture area, including portrait video; black margins are not the target. Drawing mode temporarily covers player interaction.
  • A box alone does not save an annotation.

Review

Attach a note to spoken words

Transcript anchors are optional word links for a matching rendered version.

Availability: Available

  1. Expand Transcript anchors after selecting media.
  2. If words appear, toggle the words that belong with your note.
  3. Capture the frame, add the comment and choose Save annotation.

Notes & limits

  • Words appear only when the render-derived transcript matches the exact media hash. A source transcript or older render transcript is not enough.
  • If no matching transcript appears, use frame/time notes and ask Codex to create or repair the matching render transcript. Word selection does not edit speech.

Review

Find a saved note

Feedback on this version shows the notes attached to the selected media.

Availability: Available

  1. Select the original reviewed version in Viewing.
  2. Click a note’s time to seek and pause at that moment.
  3. Inspect its text, saved frame, region, range end and transcript IDs when present.
  4. Expand History to see recorded status changes.

Notes & limits

  • If the file is missing or changed, historical feedback can remain visible but it is not proof that the current file is the original reviewed media.

Review

Move a correction through review

Each status change needs fresh Resolution notes.

Availability: Available

  1. Expand Resolve or reopen on the original note.
  2. Choose the actual Replacement revision and enter Resolution notes explaining the correction.
  3. For an open note, choose Addressed. Then add notes again and choose Ready for review.
  4. Play the replacement revision and inspect the correction. Return to the original note, add notes, and choose Accept correction only when you accept it.

Notes & limits

  • Allowed changes: open → addressed; addressed → ready for review or open; ready for review → accepted, addressed or open; accepted → open.
  • Addressed, Ready for review and Accept correction require a replacement revision. Codex must never accept owner feedback on the owner’s behalf.

Review

Reopen a correction

Use Reopen when a previously handled issue still needs work.

Availability: Available

  1. Find the note on its originally reviewed version.
  2. Expand Resolve or reopen and write Resolution notes explaining why it needs more work.
  3. Choose Reopen.

Notes & limits

  • Reopen is available from addressed, ready for review or accepted. It does not require a replacement revision.
  • Status buttons are disabled when the transition is invalid, notes are blank, a required revision is missing or an action is busy.

Resources

Set project resource preferences

Provider preference records your preferred tool for each kind of work.

Availability: Available

  1. Open a production and choose Resources.
  2. Choose a Provider preference in each relevant group.
  3. Wait for the save to complete before sending the next Codex task.

Notes & limits

  • Choices are saved with this project and included in handoffs. They do not start generation, download models, establish readiness or approve hosted use.
  • Use one heavy local inference job at a time on the 24 GiB M4. Other workers are not configured automatically.

Codex & QA

Codex & QA

Stop a running task

Stop task requests an interruption.

Availability: Available

  1. Choose Stop task while Codex is working.
  2. Wait for the task state to settle and inspect any response or error.
  3. Ask Codex to report completed files and unfinished work before continuing.

Notes & limits

  • Stopping does not undo files already written or guarantee universal resume. Earlier successful artifacts should be preserved.
  • For an interrupted native image request, recover the existing output before considering another approved request.

Codex & QA

Answer a question or approval request

Codex needs your response appears when a task is waiting.

Availability: Available

  1. Read the displayed request details.
  2. For questions, fill the answer fields and choose Send answers.
  3. For an action request, choose Approve this action only for the described scope, or choose Decline.

Notes & limits

  • Copying an example or selecting a route is not approval. Approval of one action does not authorize unrelated hosted generation or publication.
  • If details are unclear, decline and describe the intended boundary in your next request.

Codex & QA

Read production QA findings

Availability: Available

  1. Expand Before, During or After in Final production QA.
  2. Read the displayed failures under pending / findings.
  3. Ask Codex to fix or explain each finding, record actual evidence and refresh the production.

  • A passed technical check or successful render is not visual acceptance, listening or owner approval. A new edit can invalidate a previous completion.
  • Codex owns routine checklists. If actual listening or playback cannot be performed, the review remains pending and the required intervention must be stated.

Example request

Read all current production rules and QA findings. Perform available checks, record evidence individually, and identify any review still pending. Do not claim completion from rendering alone.

  2. Provide raw footage, audience, desired length and required content.

Production skills

Remove bad takes and tighten pacing

Ask Codex for $clean-cut. Expected result: cut decisions, tight/natural previews, a master and its matching timed transcript.

Availability: Available with limits

  1. Open the production and save its brief.
  2. Provide raw clips, intended order, key names/terms and anything that must stay.
  3. In Codex & QA, ask for $clean-cut and describe the result you want.
  4. Compare the proposed cuts and rendered previews; use the optional browser cut editor if detailed boundary changes are needed.
  5. Review cut decisions, tight/natural previews, a master and its matching timed transcript before using it in the production.

Notes & limits

  • Tight and natural are starting profiles, not universal pacing rules. Unknown word timing must be corrected before cutting.
  • Codex checks fresh speech recognition over the render and listens to flagged joins. Equal durations do not prove lip sync.

Example request
