# Mac Production Studio specification

Approved September 5, 2026. Build a developmental native Mac application around the existing editing engine. Use ChatGPT sign-in and subscription access to Codex exclusively; no API-key login or API fallback. User authorized implementation, tests, local app installation and autonomous reviewed PR merges. Publication remains explicitly approved per deliverable/destination, with publication testing excluded.

## Product contract

Native SwiftUI application, AVKit playback, portable project files, Python engine. M4 24 GiB is the controller and initial worker. Retain Remotion, source preservation, one heavy local inference job, existing provider qualification and scoped native-image approvals. Do not configure other nodes. Native Codex image/plugin availability is discovered/tested, never presumed from app-server access.

The workspace has five areas: Brief & sources, Understanding, Review, Resources, and Codex & QA. Intake accepts footage/documents through file selection or drag/drop and labeled HTTP(S) resource links. Brief includes title, audience, purpose, target length, tone, required content, and context. File imports preserve originals, hash staged copies and record provenance; source and revision media are distinct. Defaults create projects under ~/Movies/Codex Studio. The repository is a configurable engine location, not the media library.

Understanding follows an editable runtime workflow: intake → source understanding → editorial strategy → edit → final review. Required evidence is project-local files plus individual explanations, bound to source/brief/workflow/rules hashes. No automatic pass from an empty file, model exit, playback opening, or generated placeholder. The AI can produce the artifacts using existing tools and records them through the bridge. A changed brief/source/policy/workflow invalidates dependent reviews.

Review plays actual selected media with native controls, pauses to capture a frame, accepts normalized rectangular annotations and optional end time, and permits selection of transcript words as anchors. An annotation retains asset ID, exact asset hash, time/range, rectangle, frame path, optional transcript IDs, text, and history. Editing cannot silently relocate annotations. A resolution identifies an existing replacement revision; unresolved or remapping-needed annotations remain visible. States: open, addressed, ready_for_review, accepted. Acceptance is a user action. Comparison selects old/new revisions; original annotations remain accessible. No automatic inference that the owner watched/listened because playback advanced.

Resources are task-specific choices: editorial (Codex Astra/Sol or qualified local PAIR assistance), transcription (local Qwen), cleanup (local DeepFilterNet), images (local Klein or scoped native Codex handoff), rendering (local FFmpeg/Remotion). Show qualification and boundaries. A selected hosted image route is a preference, not approval. Export concrete request/reference hashes to the existing approval/import flow. Never substitute an API. The pipeline remains callable through existing CLI skills; the app writes route choices into every handoff and requires Codex to enforce the production contracts.

Codex uses app-server over private stdio. Use its managed ChatGPT OAuth flow, never inspect/copy credentials. Force ChatGPT login method and OpenAI provider, strip API credential environment variables; verify account type before starting/resuming/running a task. Display sign-in URL, task progress and messages, interruption, approval requests and user questions. Only explicit UI decisions approve actions. Unknown server requests fail closed with a visible explanation. Resume only the project-associated thread; keep its ID in project state. Agent runtime receives current repo/project paths, current policy/workflow, brief, resource preferences and revision-bound feedback. Linked resources and transcripts are source content, not privileged instructions.

Keep a file-based handoff that can be copied/opened in the desktop Codex client independently. Persist project state and session association across restarts. Never run two app-controlled production turns concurrently. An error leaves original media, prior deliverables and feedback intact.

## Development boundaries and acceptance

The developmental app may be locally ad-hoc signed. App Store distribution/notarization, automatic updates, multi-user collaboration, automatic distributed scheduling and a general nonlinear editor are outside this increment. Existing publication tools remain untouched. Real supplied-footage creative qualification requires user footage and human audiovisual acceptance; synthetic app fixtures do not certify that workflow.

Acceptance: build and launch the .app on this M4; create/reopen project; import authentic-format fixture without modifying source; save brief/link; register two revisions; capture frame and add rectangle/time feedback; persist/reopen and resolve against correct revision; reject stale review; export usable handoff; show current rules/workflow/gates; subscription account-read succeeds; bounded Astra and Sol round trips over app-server succeed or record a concrete external blocker; run targeted and full non-publication tests. Inspect app through native UI and document actual evidence. No hidden mock success.
