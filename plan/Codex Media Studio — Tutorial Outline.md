# Codex Media Studio — tutorial outline

## Decision

Make the first tutorial a short, authentic walkthrough of editing supplied footage. Use the user guide as its script authority. A separate capability tour can explain the broader skill library. Do not attempt one video that demonstrates every skill: local avatar/video diffusion and generative music remain deferred, publication testing is excluded, and production rule R16 says not to force every capability into every video.

This is a recording outline, not a rendered or QA-approved production. No media was generated for the documentation release. The guide is usable immediately; a tutorial should follow verified UI behavior rather than delay delivery of the help system.

## Main tutorial: from footage to reviewed revision

Target length: approximately 5–7 minutes. Each chapter answers one practical question and uses the same sample project throughout.

| Chapter | What the viewer learns | What to show |
|---|---|---|
| Start a project | Where the footage and brief go | New, import a short non-sensitive source clip, fill in audience/purpose/length/tone/keep/context, Save brief. Explain originals are preserved. |
| Give useful context | How to distinguish evidence from inspiration | Add one clearly labeled resource link. Explain adding a link does not download it. Open Help for this tab and return to the same draft. |
| Understand before cutting | Why the editor needs a content map and strategy | Ask Codex to inspect the source, record its understanding and propose an edit. Show the actual evidence and stage status; do not fabricate a completed stage. |
| Choose resources | What the preferences do | Show local defaults and the separate Codex model choice. Explain preferences do not install models or authorize hosted work. |
| Request the first edit | How to give an actionable editing request | Use a guide example, adapt it, and send it through an authenticated subscription session. Show progress and actual outcome. Exclude login credentials and private account details. |
| Review and revise | How to give precise feedback | Play the real output, pause, capture a frame, mark a region/range and save a comment. Ask for a correction; select its actual replacement revision. Leave Accept correction to the owner. |
| Check delivery | What “finished” means | Show real before/during/after findings, full playback/listening checks, and the final revision. Explain export is separate from publication. End with How to Use search. |

Do not present simulated progress, generated screenshots, or prerecorded successful statuses as live execution. Record genuine application interaction. Cut repetitive waiting only when labeled honestly.

## Skills to use only where they serve this tutorial

- `brand-setup`: establish the tutorial's own visual style; use Codex Media Studio's approved ivory/coral/graphite identity for app explanations.
- `clean-cut`, `clean-audio`, `edit-video`: edit real narration/footage, clean only where needed, and assemble the tutorial.
- `make-tsx` or `vidtsx-2d-generator`: short chapter labels and a simple workflow diagram with Remotion.
- `fake-screencast`: optional clearly labeled explanatory callout based on real screenshots, never evidence that a button or workflow works.
- `voiceover`: only with an explicitly supplied, authorized reference voice and transcript; otherwise use recorded human narration. Do not reuse another person's voice.
- `suggest-sfx` and `music`: restrained catalog/procedural accents only when they improve clarity; keep instructions intelligible.
- `thumbnail` and `packaging`: accurate title/thumbnail describing the actual tutorial. Local images are the default; native Codex generation requires its scoped approval.
- `shorts`: optional focused excerpt after the full tutorial works; verify framing and caption safety independently.
- `tracker`: register real assets/status and require current completion evidence.

## Separate capability tour

Use brief text explanations and links to the corresponding Production skills articles for all 18 skills, including `generate-image`, `generate-video`, `avatar`, and `publish-video`. Mark deferred features explicitly. Do not invoke hosted services, download large models, create a false avatar demonstration, or upload a tutorial to illustrate a menu option.

## Recording inputs and acceptance

Choose a short source clip that can be shared, an intended narration method, and a clear edit objective before media production begins. The raw-footage workflow still needs authentic audiovisual qualification; existing synthetic fixtures do not settle that requirement.

Register a Studio project and read the current production rules before production, at editing checkpoints and at final QA. Run media actions through the quality coordinator. Check every instruction against the installed app, verify text legibility at delivery size, listen to the entire soundtrack, watch the whole export, independently check retained speech, and record actual evidence. A render exit code is not acceptance. Publication remains a separate explicit decision.
