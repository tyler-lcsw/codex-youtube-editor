Audio-First Visual Podcast Mode

Implementation plan · 7 September 2026 · Status: approved for autonomous development

Goal. Let Codex Media Studio turn a 25–45 minute, single-speaker audio recording into a complete branded visual episode. Associated camera footage is optional enrichment. Audio remains the canonical timing and editorial source.

Confirmed product contract

  • One speaker only. Do not add diarization, guest logic, reaction layouts, or multicamera switching.
  • An audio-only source must be sufficient for a complete production.
  • The continuous base is a branded, restrained, audio-reactive stage. Custom visuals appear at semantically justified moments.
  • Optional camera footage participates in the same project and visual score; it does not create a second workflow.
  • Visual density is a preference, never a fixed effects-per-minute rule.
  • All generated plans, visuals, and renders remain reversible, provenance-bound, and subject to current production-quality gates.
  • No hosted fallback, implicit model download, synthetic presenter, publication test, or upload.

Architecture decisions

Audio-canonical project state

Studio records one primary audio-bearing source and an optional video-bearing camera source. Imported assets retain durable stream capabilities. Source configuration is explicit and reversible; no file is selected automatically and camera synchronization is not inferred.

Dedicated data-driven Remotion composition

The podcast stage does not use the legacy shot registry, whose compositions have literal durations and no input props. A separately registered composition consumes a versioned descriptor, derives duration through Remotion metadata, and renders video-only before the canonical mastered audio is muxed and verified.

One workflow, additive stages

The existing intake, source-understanding, editorial-strategy, edit, and final-review workflow remains authoritative. Podcast source choices bind to evidence staleness only when podcast mode is configured. Episode-map and visual-score requirements are introduced only when their implementation exists, so general and legacy projects are not blocked prematurely.

Preview before long render

Chapter and representative previews are the ordinary iteration unit. A short fixture proves plumbing; a measured render of at least 25 minutes is required before claiming long-form operational readiness.

Pull request sequence

PR 1 — Audio-canonical project contract

Outcome: Studio projects can explicitly record a solo podcast’s canonical audio and optional camera source through the Python bridge and handoff.

  • Add per-asset stream_types discovered from the actual imported bytes.
  • Add additive, schema-version-1 podcast settings with fixed solo/audio-first semantics.
  • Add patch-style set_podcast_settings and explicit clear_podcast_settings bridge methods.
  • Require an audio-bearing source; allow one optional video-bearing source; permit the same muxed asset for both roles.
  • Reject documents, revisions, unknown assets, wrong stream types, and changed bytes.
  • Probe older assets lazily when selected, preserve unknown project and nested podcast fields, and keep unconfigured legacy projects valid.
  • Include active podcast configuration in workflow input binding so changed settings stale dependent reviews.

Verification: focused red/green Python tests; full Python suite excluding publication; skill audit; whitespace check.

PR 2 — Native podcast setup and audio-only review

Outcome: A user can configure the audio-first project from the Mac app and create time/range annotations even when no video frame exists.

  • Add strict StudioCore parsing and request payload helpers for podcast settings and media capabilities.
  • Add a “Solo podcast visuals” group to Brief & sources with primary-audio, optional-camera, and density controls.
  • Truthfully label configuration as setup only until visual generation exists; never imply camera synchronization.
  • Allow audio-only playback markers and time/range/transcript annotations without frame captures.
  • Keep region drawing and provenance-bound frame annotations video-only.
  • Add synchronized help content and coverage for setup and audio-only review.

Verification: native red/green checks through tools/build_studio_app.py --checks; focused bridge/help tests; release app build; audio-only and muxed-video fixture launch checks. Visual creative acceptance is not claimed.

PR 3 — Branded waveform stage and render proof

Outcome: A configured audio source can produce a provenance-bound branded visual master with synchronized canonical audio.

  • Add a versioned podcast-stage descriptor schema containing immutable audio identity, render settings, visual identity, bounded waveform data, chapters, and standard/reduced motion.
  • Extract and cache a compact speech-energy envelope without loading full long-form PCM into memory.
  • Add a reusable, frame-driven PodcastStage component and explicit data-driven Remotion composition.
  • Add a dedicated renderer with one-worker default, staged replacement, progress reporting, audio muxing, and render receipt.
  • Render and inspect a short silence/tone/chapter-boundary fixture under the local/network boundary.
  • Preserve prior successful outputs when descriptor validation, rendering, or mux verification fails.

Verification: descriptor/envelope/cache unit tests; TypeScript typecheck; short real render with stream/frame/duration/A&V checks; representative frame inspection; skill audit.

PR 4 — Semantic visual score and Studio review

Outcome: The user can review chapter-scoped visual proposals before they mutate or render an episode.

  • Add versioned episode-map and visual-score schemas with transcript anchors, purpose, treatment, timing, asset provenance, camera policy, and an explicit unchanged/base-stage option.
  • Support five initial visual primitives: chapter card, quote/key point, progressive list, simple diagram/comparison, and image/source card.
  • Add restrained, balanced, and illustrative preferences without universal cadence rules.
  • Add append-only decisions and revision binding; owner acceptance remains an explicit user action.
  • Add chapter-level Studio review, representative previews, and a whole-episode visual-density timeline.
  • Route actual media actions through the production-quality coordinator and stale downstream evidence after changes.

Verification: schema and decision-state tests; native checks; short end-to-end project; accessibility and reduced-motion inspection; current production-quality gates. A model proposal is never itself approval or rendered evidence.

Qualification — Long-form readiness

Outcome: prove the completed pipeline operates safely at the intended duration.

  • Run one actual 25–45 minute, 1080p30 audio-first production or representative authorized source.
  • Measure wall time, peak memory pressure, output size, cache behavior, and interruption recovery.
  • Fully decode the output and measure frame count, audio duration, and A/V drift.
  • Inspect representative chapter frames and complete normal-speed audiovisual review.
  • Record honest limitations and do not infer creative acceptance from technical success.

Cross-PR acceptance

  • Each PR begins with a failing behavior test and lands only with focused and regression checks passing.
  • Each PR is independently reviewable and revertible; shared contracts land before dependent UI or renderer work.
  • Documentation and end-user help describe only behavior that exists in the merged revision.
  • Existing project JSON preserves unknown fields and remains readable.
  • Original audio, optional video, successful outputs, and review history remain durable.
  • No publication tests or uploads are performed.

Deferred beyond this track

Multiple speakers, diarization, guest/reaction layouts, multicamera direction, synthetic avatars, lip-synced presenters, arbitrary generated video, and automatic short-form extraction remain outside this implementation. They require separate product decisions and qualification.
